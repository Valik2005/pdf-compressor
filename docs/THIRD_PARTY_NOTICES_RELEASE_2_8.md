The release includes `native-source-mapping.json` and the independent `native-collection-sources.json` build-stage provenance report, which classify all embedded DLLs/PYDs and capture the *actual* source byte hash, size, and sanitized Python/Windows/wheel installation scope for each file. This is independently compared with all extracted DLL/PYD bytes in the EXE. The **historical pre-PR42** build had 118 native DLL/PYD entries including **53 Microsoft runtime** entries (42 API-set DLLs, 10 MSVCP/VCRUNTIME copies, 1 UCRTBase) and **4 OpenSSL** libraries. The subsequent release candidate removes the unrelated MySQL `libssl-3-x64.dll` / `libcrypto-3-x64.dll` and unused Qt OpenSSL TLS plugin: **115 native members, 2 retained CPython OpenSSL libraries**, pending exact same-commit final re-audit. Microsoft runtime redistribution still requires a separate rights check. The inventory and source archive checksums are not proof of reproducible upstream-source builds, Microsoft's redistribution license, or complete Qt/AGPL compliance. The improved source collection audit traced the **former** `libssl/libcrypto-3-x64` DLLs to MySQL Server 8.4 on the Windows runner; they have now been excluded. The 42 API-set DLLs and `ucrtbase.dll` still have unclassified builder paths and remain explicit Microsoft license review items.

**External VC++ Runtime experiment caveat (not public release):** The 62-native test build replaces the historical 115-native binary and excludes all 53 Microsoft MSVC/UCRT/API-set DLLs. Requires official Microsoft x64 VC++ runtime preinstalled; Windows 10/11 client compatibility and source/EXE/license acceptance must be independently checked. Historical source audits referring to 115 included DLLs remain factual only for their exact older commit. This does not certify OSS licensing or grant release approval.

## Specific to the v2.8 release

The unsigned v2.8 release must be audited against the **exact final EXE**. Its SHA-256 is computed after the final Windows build and must match the same-run native inventory, installed-package notices, version-pinned sources and cross-audit evidence. No code-signing key, publisher certificate or Authenticode verification is claimed. The published source tag is part of the corresponding-source offer.

The main application processes PDF content locally. The unsigned release is not sent to SignPath; it contains no signing credentials or users' PDF documents. Users can compare the published SHA-256, but a checksum is not a certificate of publisher identity.

**Compliance gate:** verification of six source archive hashes, license notices and Qt relinking instructions provides useful evidence but is not a legal conclusion about all upstream binary components, embedded codecs, supplier-specific notices, LGPL rights, or Microsoft redistributables. Unresolved obligations block release **whether signed or unsigned**.
