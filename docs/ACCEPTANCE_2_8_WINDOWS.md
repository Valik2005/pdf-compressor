# PDF Compressor 2.8 — проверка релиз-кандидата на компьютере пользователя

**Статус:** рабочая ветка, не публичный релиз. Публикуется только после Windows CI, соответствующих исходников/лицензий и проверки реального EXE пользователем. Стабильный 2.7.1 не изменяется.

## Файлы и настройки

Использовать **только оригинальные PDF из существующего тестового архива 2.7.1** (не результаты прежнего сжатия). Сохранять выходы в отдельную папку `2.8_РЕЗУЛЬТАТЫ`. Включить новую опцию **«Проверять качество после сжатия (дополнительное время)»**; после каждой операции сохранить HTML-отчёт и открыть результат.

### Критические сценарии

| PDF | Режим | Что проверять в 2.8 |
| --- | --- | --- |
| `01_Только_текст_12стр.pdf` | Сбалансированный | 12 страниц, выделяемый текст не потерян, QA без ложной ошибки; качество не ухудшилось |
| `02_Сканы_мелкий_текст_4стр.pdf` | Максимальное сжатие | 4 страницы, файл открывается, QA честно предупреждает о растровом мелком тексте; проверить знаки и печати в масштабе 200% |
| `10_Новый_цветной_контроль_3стр.pdf` | До заданного размера, 1 МБ, без downscale | Сравнить с 2.7.1 (1,06 МБ); ограниченный JPEG-поиск пробует меньшие значения только при небольшом превышении; проверить качество мелких цветных деталей |
| `10_Новый_цветной_контроль_3стр.pdf` | До заданного размера, 0,5 МБ, без downscale | Честное «Выше лимита», без обещаний, скрытого уменьшения разрешения или неограниченного JPEG-перебора |
| `06_Мелкие_иконки_10стр.pdf` | SmartFit, 0,01 МБ | Не тратить время на бесполезные пробы JPEG для крошечных значков; правильно сообщить о недостижимой цели |
| `05_Векторные_схемы_8стр.pdf` | Максимальное качество | 8 страниц и чистые векторные линии, без необоснованного ухудшения |
| `09_Большой_PDF_отмена_14стр.pdf` | 0,5 МБ + разрешён downscale | Попробовать прервать **во время реальной операции**, а не только до начала; не должны оставаться частично записанные PDF |
| Первые 5 оригиналов | Сбалансированный, пакет | Верные выходы каждого исходника, свободная работа интерфейса, отсутствие повреждений и путаницы отчётов |

### Для каждого результата

- Записать размер до/после, время, число страниц, статус, JPEG %, факт уменьшения разрешения.
- При QA-предупреждении файл **не удаляется**; визуальный риск не должен считаться ошибкой открытия или структурным повреждением.
- При одновременном предупреждении QA и недостижении лимита статус **«Выше лимита»** должен остаться видимым, а обе причины — в подробностях.
- Убедиться, что в HTML/JSON указаны фактические значения JPEG, страницы без выделяемого текста, число визуально проверенных страниц и предупреждения.
- На сканах сверить **не только общий вид страницы**, но и буквы/цифры, тонкие линии, цветные печати и подписи при увеличении 200%.
- Зафиксировать RAM и CPU **во время пакетного сжатия и QA**, потому что успешные GitHub-тесты не заменяют проверку на конкретном ПК.
- Проверить переключение RU/EN, выбор другой папки и длинные пути, предпросмотр и отмену.

## Запрет ложных гарантий

Не считать «Замечаний не найдено» сертификатом сохранности мелкого текста. Оптическое распознавание символов (OCR) в 2.8 не выполняется; качественные изменения на непросмотренных страницах могут остаться незамеченными. Цель 1 МБ означает фактический порог **1 000 000 байт** и не гарантирует достижение в каждом PDF. Если цель достигнута JPEG 27%, это не автоматически означает приемлемое качество.

**Выпуск не разрешать автоматически.** Дождаться сравнения результатов и оценки качества пользователем. Сборки GitHub Actions, отмеченные `NOT FOR RELEASE`, остаются тестовыми.
