## Подтверждение точности на исходном PDF №10

Дополнительные **локальные**, независимые пробы без изменения разрешения исходных JPEG-снимков (размеры файла могут отличаться между версиями PyMuPDF):

| Кодирование | Размер итогового PDF |
| --- | ---: |
| JPEG 30%, 4:4:4 (старый нижний предел) | 1 059 105 байт |
| JPEG 28%, 4:4:4 | 1 013 452 байта |
| JPEG 27%, 4:4:4 | **988 503 байта** |

Опыт подтверждает, что цель **1 000 000 байт** можно достичь в таком примере **без уменьшения разрешения**, снизив JPEG с 30 до 27%. Но это дополнительная потеря качества картинки, а не безусловное улучшение. Измеренная средняя RGB-разница при отрисовке первой страницы относительно оригинала: JPEG 30% — приблизительно 3,28/255, JPEG 27% — 3,43/255. Это **не метрика читаемости мелких символов**, поэтому визуальная проверка после обработки обязательна.

## Алгоритм 2.8

1. Основной поиск и ограничения качества — как в 2.7.1.
2. Только для режима **«До заданного размера»** (не для консервативного SmartFit): если после обычного поиска файл превышает лимит **не больше чем на 8%**, и документ содержит изображения, опробовать JPEG 28%. Если он по-прежнему слишком велик — JPEG 27%, иначе для лучшего качества проверить JPEG 29%.
3. **Не больше двух дополнительных JPEG-прогонов**, без изменения количества пикселей, при этом возможна отмена.
4. Если результат уложился — сохранить самый высокий достигший цели JPEG из проверенных вариантов; иначе оставить наилучший прежний результат и показать корректное превышение.
5. При большем превышении этот подбор **не запускается**, чтобы не тратить CPU и не деградировать мелкий текст без реальной перспективы достижения цели.
6. Для режимов **«Максимальное качество» (95%), «Сбалансированный» (85%), «Максимальное сжатие» (48%)** кодирование остаётся прежним. SmartFit сохраняет отдельные консервативные ограничения качества.
7. В GUI статус **«Выше лимита»** не обрезается, а полный текст и точное превышение в байтах доступны в подробностях / подсказке.

## Проверки

- Регрессионный тест создаёт трёхстраничный цветной PDF и динамически подбирает бюджет между JPEG 30% и 27%; подтверждает достижение цели, неизменность выделяемого текста, страниц, исходного файла и количества пикселей.
- Отдельные тесты запрещают подбирать JPEG ниже прежних ограничений SmartFit и проверяют отсутствие лишних попыток для заведомо невыполнимой цели.
- Тест интерфейса проверяет сокращённый статус, точную величину превышения и полный путь каталога.
- Windows CI должен пройти для Python **3.13 и 3.14**, затем проверку Windows onefile.
- На ПК пользователя сравнить 30% / 27% на №10 в масштабе **200%**, отдельно мелкие цветные подписи и печати. Итоговое решение о публичном релизе **не принимать только по средней RGB-разнице**.

**Ограничения:** размер JPEG может быть немонотонным; два дополнительных прогона не гарантируют идеальный подбор или достижение любого лимита. При 0,5 МБ у №10 слишком большой разрыв — автоматического агрессивного ухудшения качества не выполняем.
