## Почему этот путь

SignPath Foundation предлагает **бесплатную** подпись некоторым подходящим Open Source проектам; сертификат выпускается на *SignPath Foundation*, а не на личное имя разработчика. Отбор производится самой организацией, поэтому положительный исход **не гарантирован**.

Официальные требования:
- https://signpath.org/terms.html
- https://signpath.org/apply
- https://docs.signpath.io/origin-verification/

## Что уже есть

- Публичный репозиторий: https://github.com/Valik2005/pdf-compressor
- Лицензия исходников **AGPL-3.0**, одобренная OSI, опубликована в `LICENSE`.
- Опубликованный релиз Windows EXE 2.7.1 и документированные функции в README (RU/EN).
- В GitHub Actions собирается проверочная Windows onefile-сборка на основе репозитория. Есть PyInstaller spec, тесты Python 3.13/3.14 и инвентаризация лицензий нативных DLL.
- Обработка пользовательских PDF выполняется локально, без отправки содержимого PDF на серверы.

## Обязательные проверки до заявки

1. **Право на подпись и лицензии всех зависимостей.** Убедиться, что все включённые компоненты имеют допустимые OSS-лицензии и что лицензии, исходники и обязательные notices доступны. Проверки зависимостей — отдельный обязательный этап; один AGPL-файл в корне не является доказательством соответствия всего EXE.
2. **Привязка бинарника к источнику.** Подписывать только завершённую сборку из публичного GitHub Actions workflow, из защищённой ревизии / тега, без ручной замены EXE. Для релиза заранее зафиксировать sha256 и манифест.
3. **Политика подписи.** На главной странице проекта и в публичной релизной документации должен быть явно виден пункт **“Code signing policy”** с пометкой «Free code signing provided by SignPath.io, certificate by SignPath Foundation» **только после соответствующей настройки / одобрения**, либо с прозрачным состоянием «application pending» до одобрения.
4. **Роли.** Назначить реальных авторов/рецензентов и человека, утверждающего каждый запрос подписи. Не выдумывать участников. Подписывание требует ручного разрешения для каждого релиза.
5. **Безопасность аккаунта.** Владелец проверяет использование MFA в GitHub и SignPath. Не хранить ключи и секреты в исходном коде или публичных CI-логах.
6. **Данные и конфиденциальность.** Опубликовать точное заявление о приватности: программа не пересылает документы в сеть. Описать поведение зависимостей, если в будущем появятся внешние запросы.
7. **Официальная заявка.** Владелец проекта проходит форму https://signpath.org/apply и подтверждает права на репозиторий. Принятие заявки и настройка подписания зависят от SignPath Foundation.
8. **Только после одобрения:** добавить проверяемое `GitHub Actions` подписание через SignPath.io, ограничения веток/тегов, временную метку, проверку Authenticode и SHA-256 **после** подписи. В релизе публиковать только финальный подписанный EXE и соответствующий манифест/лицензии.
9. **Только после успешного испытания 2.8 на Windows пользователя:** слить изменения, подготовить проверенный релиз и отдельно получить решение пользователя о публикации.

## Если SignPath Foundation не одобрит проект

Проект продолжает существовать **бесплатно и без подписи**. Не использовать самоподписанный сертификат в качестве притворно доверенной подписи: он не убирает SmartScreen. Не отключать системные механизмы защиты Windows ради распространения программы. Сохранять публичный GitHub release, HTTPS-ссылки, SHA-256 и воспроизводимые проверки.
