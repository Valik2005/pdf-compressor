# Как получить и опубликовать PDF_Compressor_2_6.exe на GitHub

## 1. Создай репозиторий

В аккаунте GitHub создай новый **пустой** репозиторий `pdf-compressor` (сначала желательно **Private**) по адресу https://github.com/new. Не добавляй README, .gitignore или лицензию при создании: они уже подготовлены в проекте.

## 2. Загрузи этот проект

Установи Git for Windows с https://git-scm.com/download/win, если его ещё нет. Распакуй архив проекта и запусти `Publish_to_GitHub.bat`, вставь URL нового репозитория, например `https://github.com/USERNAME/pdf-compressor.git`. При необходимости Git предложит авторизацию.

## 3. Получи EXE автоматически

При отправке на ветку `main` запускается **Actions → Windows EXE and Release**. Сборка происходит на Windows x64 в облаке; Python на компьютере будущего пользователя не нужен. Готовая программа появляется в результате выполнения workflow в разделе **Artifacts** (можно скачать ZIP с EXE).

## 4. Прикрепи EXE в Releases

В том же разделе **Actions → Windows EXE and Release** нажми **Run workflow** и оставь версию `v2.6.0`. Workflow создаст **черновик (Draft) релиза** и прикрепит к нему `PDF_Compressor_2_6.exe`.

Открой вкладку **Releases**, найди черновик `v2.6.0` и проверь EXE и текст релиза. Публиковать **публично** следует только после проверки лицензий PyMuPDF / PySide6 и включения необходимых уведомлений (см. `DEPENDENCIES_AND_LICENSING.md`). После публикации любой пользователь публичного репозитория сможет скачать EXE непосредственно из **Releases → Assets**.

## Примечания

- EXE не подписан сертификатом издателя: Windows SmartScreen может предупредить о неизвестном разработчике.
- `--onefile` упаковывает всё в один EXE, но первое открытие может быть медленнее.
- Сжатие PDF работает офлайн, без загрузки документов на сервер.
- Windows-EXE можно собирать локально через `Собрать_EXE.bat`, но автоматический GitHub Actions избавляет тебя от этой необходимости.
